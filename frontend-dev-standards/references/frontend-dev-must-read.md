# 前端开发必读规范

本文是通用前端开发前置规范，随 `frontend-dev-standards` skill 分发。每次新增或修改页面、组件、样式、路由、API 适配、Mock、测试或前端契约前先读；项目已有更具体规范时，以项目规范为准。

## 1. 先确认需求

开工前先复述本次要产出的页面、入口、用户角色、核心动作、成功标准和不做范围。需求必须符合真实业务流程；涉及提交、审核、确认、删除、停用等动作时，要明确状态流转、权限、二次确认和终态是否可改。

## 2. 字段和契约

页面字段必须能追溯到数据库字段、API 字段、稳定关联查询、聚合结果或前端固定字典。先区分“用户输入、系统生成、登录上下文、审计填充、业务推导、只读展示”；只读字段不得进入提交 DTO。筛选控件一个对应一个明确查询参数，避免含义不明的全局 `keyword`，除非业务明确需要并写清匹配列。

## 3. 组件复用

优先复用项目已有组件库、表格、弹窗、滚动区、选择器、按钮、标签、分页、加载遮罩、空状态和错误提示。新增样式前先查相似页面；不要为单个页面手写一套按钮颜色、弹窗布局或表格明细。没有现成组件时，先抽通用组件再落业务页面。

## 4. 表格和列表

列表结构保持稳定：标题说明、摘要、筛选、工具栏、数据区、分页。表格列必须有明确宽度策略，右侧时间列和操作列不能重叠；需要横向滚动时，滚动条在表格视口内可用。sticky 表头必须实底和足够 z-index，不能和滚动内容叠字。摘要只展示业务指标，不展示总条数或当前页行数这类分页控件已表达的信息。

## 5. 表单和弹窗

新增、编辑、详情、提交、审核、确认要共享一致字段定义。编辑弹窗必须带出原数据；草稿/待确认等可编辑状态要明确哪些字段能改，终态默认只读。长弹窗受视口约束，正文滚动，底部按钮可见。提交、审核、确认这类不可逆或重要动作必须先展示完整详情，再让用户确认。

## 6. 交互状态

查询、重置、刷新、分页、每页条数切换使用短防抖、请求序号和加载反馈；写操作必须提交锁，接口完成前禁用重复操作。状态不能用普通下拉任意改，要按业务动作按钮触发。保存后列表、详情和表单回显必须一致。

## 7. 视觉统一

字体、按钮、标签、间距、筛选宽度、弹窗背景、表头、行高和空状态跟随项目设计系统。文字不能溢出按钮或单元格；长备注、长名称、长编号要截断并提供悬停或详情查看。不同业务类型的标签要有可区分颜色，但不能破坏整体配色。

## 8. 验证和维护

完成后至少做契约检查、构建、相关自动化或 smoke、真实浏览器截图。截图要覆盖主视口、窄视口、弹窗、展开明细、右侧操作列和滚动状态。
