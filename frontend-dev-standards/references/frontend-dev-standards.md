# 前端开发规范

## 1. 先找现有模式

实现前先检查：

- 共享 UI 组件
- 信息密度相近的表格/列表页面
- 已有弹窗、抽屉、浮层、选择器、标签、空状态、加载遮罩
- 颜色、间距、圆角、字体、焦点态等设计 token

优先复用。需要新增模式时，必须让它可复用，并说明为什么现有模式不够。

历史经验：不要一上来就改 CSS 数字。先找到相似页面或组件，确认它用什么 class 或组件解决布局，再有意识地复用。很多回归来自手写表格、手写弹窗间距、手写按钮颜色和一次性滚动容器。

## 2. 数据契约纪律

每个 UI 字段都要知道来源：API/schema、数据库/实体模型、关联查询、聚合、用户输入、登录上下文、审计字段或前端字典。

规则：

- 表单 DTO 只包含可编辑的用户输入字段。
- 只读、来源、系统生成字段用文本展示。
- 列表、详情、编辑页面使用同一份字段模型。
- API 适配层负责在边界处转换类型。
- 契约字段缺失或非法时，开发阶段要尽早暴露。
- 不要求后端返回没有稳定来源的字段；如果已有源数据足够，路径、友好标签、中文名等展示值优先由前端派生。
- 不把 `all`、空字符串、展示文案、路径文案或前端专用字段发送到 API。

## 3. 表格和列表

高频问题直接转成规范：

- 加数据前先设置稳定列宽或最小宽度。
- 操作列不换行，并保持按钮风格一致。
- 宽表在表格视口内提供横向滚动。
- sticky 表头必须是不透明背景，并有正确 z-index。
- 展开行要和主行有视觉区分。
- 摘要区不要展示总行数或当前页条数。
- 测试数据必须包含长名称、长编号、长备注、空值和窄视口。

写表格前先做列计划：

```text
列名 | 字段来源 | 宽度/最小宽度 | 对齐 | 空值展示 | 长文本处理
```

主从表格要分清父行和子行。父行展示记录身份和状态；子行展示明细数据。不要把来源、类型、状态、操作等字段混进一个列里。

## 4. 表单、弹窗和详情

- 新增、编辑、详情必须共享同一份字段清单。
- 编辑弹窗必须预填当前数据。
- 长弹窗需要视口最大高度、正文滚动和可见底部按钮。
- 重要动作必须先展示详情预览，再二次确认。
- 嵌套确认弹窗必须阻止点击和聚焦到底层弹窗。
- 长文本用 tooltip、popover、展开或详情页查看全文。
- 系统生成编码、审计字段、负责人字段、计算值必须只读或隐藏。
- 货币和单位要在控件内或标签旁可见，但不能混入提交数值。
- 同一交互区域同一时间只能打开一个 dropdown/popover。

弹窗流程规则：

1. 先定义一次字段清单。
2. 标记每个字段为可编辑、只读、系统生成或隐藏。
3. 测试空新增、填充新增、编辑预填、详情只读和确认预览。
4. 中等高度视口下底部按钮必须可达。

## 5. 交互状态

异步 UI 必须具备：

- 查询、重置、刷新、分页、每页条数切换使用短防抖。
- 用请求序号或取消机制忽略过期响应。
- 受影响区域显示 loading overlay 或 skeleton。
- 忙碌期间禁用重复触发。
- 新增、编辑、删除、审核、确认、批量动作必须有提交锁。
- 成功和失败反馈要对应具体动作。

分页点击后要立刻有反馈：锁定分页区域，显示同一套列表加载层，忽略过期响应。不能等网络请求真正发出后才反馈。

## 6. 视觉一致性

- 使用项目字体层级，不发明单页字号。
- 使用现有按钮变体和语义颜色。
- 状态和类型标签要有稳定可区分颜色。
- 控件内文字不能溢出或重叠。
- 页面留白和区块节奏跟随同类页面。
- 后台工具不要嵌套卡片、堆装饰或做一次性色彩系统。

## 7. 实现前清单

不知道这些之前不要动手：

- 已查看相似页面/组件。
- 字段清单已完成。
- 表格列计划或表单字段计划已写。
- 异步操作已识别。
- 浏览器 QA 场景已列出。
- 可能变化的文档/契约已识别。

如果改动共享 UI，至少规划一个使用该共享组件的旧页面回归检查。

环境核验：

- 确认当前分支/工作区是目标分支。
- 确认 app 目录和包管理命令属于当前项目。
- 启动报旧依赖时，检查依赖文件和 `node_modules` 是否匹配。
- 本地截图和调试文件不要进入提交，除非它们是明确需要的产物。

## 8. 长期维护位置

开发规范需要自进化，但要写到固定位置：

- 高频通用前端规范：更新 `frontend-dev-standards/references/frontend-dev-must-read.md`。
- 本 skill 的详细开发规则：更新 `frontend-dev-standards/references/frontend-dev-standards.md`。
- 浏览器验收步骤或截图场景：更新 `frontend-browser-qa/references/frontend-product-qa-checklist.md` 和 `frontend-browser-qa/references/browser-qa-checklist.md`。
- 用户认可后的重复问题解决方案：更新 `frontend-fix-loop/references/frontend-issue-record.md`。
- 技能包说明、调用边界或新增子 skill：更新 `frontend-skill-index/references/frontend-skill-package.md`。

如果规范里已经写了但执行时漏掉，要强化原条目措辞；如果规范没有覆盖，补新条目。
