# 前端需求门禁

## 工作流程

1. 阅读 `references/requirement-checklist.md`。
2. 用具体 UI 语言复述本次目标：页面、入口、用户动作、可见结果和不做范围。
3. 明确每个展示字段、可编辑字段的数据来源。
4. 先梳理业务状态和动作，再设计页面；例如草稿、已提交、已审核、已确认、停用、删除、失败等，或项目自己的状态。
5. 判断是否可以直接开发。若缺失信息会导致数据错误、权限错误或不可逆动作错误，先问用户；否则写明假设后推进。

## 输出要求

编码前输出简短需求摘要：

- 用户目标
- 涉及页面或组件
- 字段和数据来源
- 状态和动作
- 校验与验收项
