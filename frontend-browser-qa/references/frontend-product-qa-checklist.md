# 前端浏览器 QA 清单

本清单随 `frontend-browser-qa` skill 分发，用于真实浏览器截图和产品功能验收。适用于 Web 前端页面、后台系统、SaaS 工具、表单流程和数据列表。

## 1. 需求回放

- 页面入口、目标用户、核心任务和验收标准与需求一致。
- 本次新增、编辑、详情、删除、提交、审核、确认、筛选、分页等动作已列全。
- 状态流转符合业务，不存在可随意修改终态、绕过详情确认、绕过权限或绕过二次确认的问题。

## 2. 数据和契约

- 页面字段、表单字段、详情字段和接口字段一一对应。
- 只读字段不出现在提交 DTO；系统生成字段不让用户编辑。
- 新增后能查到，编辑后能回显，详情与列表一致。
- Mock、测试数据和真实接口结构一致，不用假数据掩盖契约缺口。

## 3. 操作覆盖

- 查询、重置、刷新、分页、每页条数、组合筛选全部测试。
- 新增、编辑、详情、停用/启用、删除、提交、审核、确认、取消等关键按钮都实际点击。
- 所有写操作有提交锁、加载态、成功反馈和失败反馈。
- 重要动作必须先展示完整详情，再确认执行。
- 下拉、弹窗、二次确认、分页这类共享组件改动后，至少回归一个旧页面。
- 用户用截图标出的反馈点必须转成同视口截图或自动断言。

## 4. 视觉布局

- 页面不贴边，首屏结构稳定，信息密度与同类页面一致。
- 表格列不重叠、不漂移；时间列、状态列、操作列不挤压。
- sticky 表头不透明；横向滚动条可在表格视口直接操作。
- 字体、按钮颜色、标签颜色、筛选宽度、弹窗背景和设计系统一致。
- 长文本截断合理，可通过悬停、展开或详情看到全文。

## 5. 弹窗和明细

- 新增、编辑、详情弹窗字段完整且间距合理。
- 编辑弹窗能带出原数据，不出现空选项、错位字段或无效操作列。
- 长弹窗不超过视口，正文滚动，底部操作按钮始终可见。
- 明细区默认展开/收起符合使用习惯；展开后字段对齐，不与主表头层级冲突。
- 二次确认出现时底层弹窗不可点击、不可聚焦。

## 6. 浏览器截图

- 至少覆盖桌面主视口、较窄视口和一个移动或中等宽度视口。
- 每个新增页面至少截图：列表首屏、筛选后、空状态、错误/加载态、主要弹窗、详情弹窗、关键确认弹窗。
- 表格页面额外截图：右侧操作列、横向滚动状态、sticky 表头滚动后状态、展开明细。
- 截图放入本次专用 QA 目录，命名包含路由、视口和场景。
- 截图前等待动画和短加载结束；加载态截图必须刻意在加载中捕获。

## 7. 通过标准

- 没有元素重叠、错位、截断不可读、按钮颜色混乱、弹窗遮挡、滚动条不可达。
- 页面行为和业务逻辑一致，所有新功能都可从 UI 完整走通。
- 修复后必须重新截图；不能用旧截图证明新状态。
- 用户确认通过后，可以清理旧截图目录，保留必要的最终证据或测试日志。
