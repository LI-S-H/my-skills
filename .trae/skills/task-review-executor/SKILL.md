# 任务审查执行工作流

## 触发条件

满足以下**任一条件**时触发：

| 维度 | 阈值 |
|------|------|
| 子任务数 | > 6个 |
| 预估执行时间 | > 10分钟 |
| 涉及文件数 | > 5个文件 或 存在大文件 |
| 跨领域操作 | 是（如前端+后端+数据库） |
| 用户反馈产出不符 | ≥ 2次 |

**大文件阈值：**
- 文本文件：>50KB 或 >500行
- PDF：>5MB | Office文档：>3MB | 图片：>2MB
- 音频：>5MB | 视频：>30MB | 压缩包：>15MB | 二进制：>10MB

**用户反馈不符的显式判断词：**
- 直接否定："不对"、"错了"、"不行"、"不符合"、"不是我要的"
- 要求修改："改一下"、"重新做"、"调整"、"换成"
- 遗漏质疑："少了"、"缺了"、"漏了"、"还有呢"
- 质量不满："太简单"、"不够详细"、"质量差"、"敷衍"
- 方向偏离："跑题了"、"偏了"、"理解错了"

## 角色定义

**主Agent（调度者）— 使用最强可用模型**

职责：
- 理解用户需求，进行任务分解
- 将完整任务上下文传递给子Agent
- 调度审查Agent和执行Agent
- 处理子Agent反馈，修正任务流程
- 参与投票仲裁

**上下文传递要求** — 主Agent向子Agent发送信息时必须包含：
- 用户原始需求（完整描述）
- 任务分解列表（每个子任务的目标、输入、输出、依赖）
- 已完成的工作（已完成的子任务及其产出、文件路径）
- 当前待执行任务详情
- 历史反馈记录（用户所有反馈和修改意见）
- 项目信息（项目路径、技术栈、相关文件列表）
- 约束条件（性能要求、兼容性、格式要求等）

**审查Agent — 使用最强可用模型**

职责：
- 审查任务流程规划（覆盖度、依赖关系、执行顺序）
- 验收任务产出物（完整性、准确性、格式）
- 发现问题时给出具体修改建议
- 参与投票仲裁

**执行Agent**

职责：
- 按阶段执行任务
- 执行前确认已完成任务状态
- 发现任务流程不合理时上报主Agent
- 完成后汇报执行结果

## 协作循环流程

**流程步骤：**

1. 主Agent理解用户需求并进行任务分解
2. 审查Agent审查任务流程规划
   - 不通过 → 返回主Agent修正 → 回到步骤2
   - 通过 → 进入步骤3
3. 执行Agent执行当前子任务
   - 执行前：回顾已完成任务，检查待执行任务是否仍合理
   - 发现问题 → 上报主Agent → 主Agent修正 → 审查Agent审批 → 回到步骤3
   - 无问题 → 执行任务 → 进入步骤4
4. 审查Agent验收产出
   - 不通过 → 返回主Agent → 新一轮循环
   - 通过 → 任务完成

**循环控制规则：**
- 已完成的正确任务流程不修改，除非发现错误
- 执行Agent每次执行前必须确认历史任务状态
- 同一任务流程审批超过3次（含3次）未通过 → 转人工审批

## 投票机制

当审查Agent和执行Agent意见冲突时触发：

| 参与者 | 票数 |
|--------|------|
| 主Agent | 1票 |
| 审查Agent | 1票 |
| 执行Agent | 1票 |

- 多数票方案采纳
- 平票时主Agent拥有最终决定权

## 执行模式

| 模式 | 适用场景 | 说明 |
|------|----------|------|
| 串行执行（默认） | 子任务之间存在依赖 | 按依赖顺序逐个执行 |
| 并行执行 | 子任务之间前后无关 | 可同时派发给多个执行Agent |

判断规则：子任务A的产出是子任务B的输入 → 必须串行；无数据依赖 → 可并行

## 日志与摘要机制

**日志文件：**
- 路径：项目根目录下 `_logs/` 文件夹
- 命名：`task-review-{YYYYMMDD-HHmmss}.md`
- 内容：完整讨论历史、审查意见、修改记录

**摘要机制：**
- 审查通过后仅保留最终确认的任务执行流程
- 讨论历史写入日志文件，不占用执行上下文
- 需要回顾历史决策时按需读取对应日志文件

## 需求澄清集成

在以下场景调用 `requirement-clarifier`：
- 审查Agent在审批任务流程时发现用户描述不清晰
- 审查Agent在验收产出时发现无法判断是否符合用户要求
- 执行Agent在执行过程中发现需求模糊导致无法继续

调用时必须向用户提供选项选择和自定义输入，帮助用户更好地描述需求。

## 终止条件

任务在以下情况视为完成：
- 所有子任务执行完毕
- 审查Agent验收通过
- 产出物无遗漏、无偏差、符合用户要求
- 用户确认满意（如涉及用户反馈触发的情况）
