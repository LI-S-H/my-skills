# 前端问题修复闭环

## 工作流程

1. 阅读 `references/frontend-issue-record.md` 和 `references/fix-loop.md`。
2. 修改前先复现或检查问题。
3. 搜索本地问题记录，确认是否有相似历史修复。
4. 用最小安全改动修复根因。
5. 根据问题类型运行代码检查和浏览器 QA。
6. 用户认可前不要写入永久问题记录；认可后再补充。

如果本轮用户只表达“可以了、通过、没问题、已解决、这次对了”等认可语句，先判断上一轮是否是前端修复或 QA 任务；如果是，必须回到 `references/frontend-issue-record.md`，按规则补记录或说明已有记录覆盖，不要把认可当成普通闲聊跳过。

## 重复问题处理

如果同类问题曾经出现过：

- 检查现有规范是否已经覆盖。
- 若规范已覆盖但本次未遵守，需要说明漏遵守，并强化相关规范。
- 若规范未覆盖，等用户认可修复后新增一条简短规则。
