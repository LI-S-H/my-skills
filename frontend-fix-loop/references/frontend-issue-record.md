# 前端问题记录

本文件随 `frontend-fix-loop` skill 分发，只记录已经修好并被用户认可的问题。不要在开始修复时记录；先定位、修复、验证、得到认可，再补充到这里。记录要短，便于下次命中。

| 问题 | 已确认解决方案 | 后续规范 |
| --- | --- | --- |
| 表格列重叠，时间列和操作列互相挤压 | 使用固定列宽、显式最小宽度、不可换行操作列和表格内横向滚动 | 表格实现前先规划列宽，截图必须覆盖右侧列 |
| sticky 表头透明，滚动内容和表头叠字 | 表头使用实底背景、边框和高于内容的 z-index | 所有 sticky 表头都要滚动截图检查 |
| 明细表字段过宽或混在一个字段里 | 按契约字段拆列，控制列宽，必要时使用紧凑表格或展开行 | 明细字段不得为了省事聚合成含义不清的展示列 |
| 新增/编辑弹窗缺字段或编辑无数据 | 从详情或列表源数据初始化表单，拆分可编辑、只读和系统字段 | 编辑弹窗必须实测回显，不能只看静态页面 |
| 按钮颜色、字号、形态和已有页面不一致 | 复用现有 Button、Dropdown、Tag、Dialog 变体 | 不为单页自造按钮样式 |
| 提交、审核、确认在列表直接执行 | 先打开详情或确认预览，再执行动作 | 重要动作必须让用户看到完整信息 |
| 查询、刷新、分页无加载反馈 | 加短防抖、请求序号、加载遮罩和禁用态 | 所有异步列表操作都要有即时反馈 |
| 顶部摘要展示总条数或当前页行数 | 摘要只展示业务指标；行数交给分页和表格表达 | 分页列表不要为了摘要要求后端额外 COUNT |
| 弹窗滚动条遮挡内容或底部按钮不可见 | 使用视口约束和独立正文滚动区，底部按钮固定可见 | 长弹窗必须在中等视口截图 |
| 长备注、长名称、长编号撑开布局 | 单元格截断，悬停或详情展示全文 | 长文本场景必须纳入测试数据 |
| 多个下拉框同时展开并互相覆盖 | 同一交互面只允许一个浮层打开，打开新浮层时关闭旧浮层 | 下拉组件要有互斥状态或统一浮层管理 |
| 系统生成字段被做成可输入 | 字段先分类为用户输入、系统生成、审计、上下文、推导；非用户输入只读或隐藏 | 表单 DTO 只提交用户输入字段 |
| 金额、数量等输入缺少单位提示 | 在控件内或标签旁显示货币/单位，提交仍使用纯数值 | 数值字段要同时核对显示单位和提交值 |
| 只看路由加载就认为浏览器测试通过 | 为每个用户反馈建立同视口场景，实际点击、填数、截图和断言 | UI 修复必须有新截图或自动断言覆盖原问题 |

新增记录规则：

1. 只有用户认可修复后才能新增记录。
2. 如果问题已被本文件覆盖，不新增重复行，只强化对应规范。
3. 如果问题证明 QA 流程漏项，同时更新 `frontend-browser-qa/references/frontend-product-qa-checklist.md` 或 `frontend-browser-qa/references/browser-qa-checklist.md`。
4. 如果问题证明开发规范漏项，同时更新 `frontend-dev-standards/references/frontend-dev-must-read.md` 或 `frontend-dev-standards/references/frontend-dev-standards.md`。
5. 安装或升级 skill 时，不得直接覆盖本文件里已经沉淀的用户记录；如果源包和本地安装目录都有记录，先合并去重，再保留更具体、更被验证过的说法。
